# 問題づくりのガイド

このゲームの価値は「整い場」で読む解説にあります。解説が間違っていれば、ゲームとして面白くても教材として失格です。

## 1. 出典は公式ドキュメントだけ

- 使ってよいのは、その製品やサービスの提供元が出している公式ドキュメント・公式リポジトリ・公式記事です。
- 個人のブログ、動画、SNSの投稿、AIが生成した文章は出典にしません。
- `source` 欄には「公式ページの名前」と「URL」を書きます。URLは整い場でリンクとして表示されます。
- 書く前に、そのページを実際に開いて、主張が本当に書かれているかを確かめます。

## 2. 問う内容

- 長く通用する「仕組み」と「考え方」を問います。
- ボタンの位置、料金の金額、最新版だけの機能など、すぐ変わる細部は問いません。
- 1問で確かめる知識は1つにします。

## 3. ゴウのセリフ（line）

- ゴウは自信満々に断定します。正しいことも、間違ったことも、同じ口調で言います。
- 間違いのセリフは、初心者が本当に思い込みそうなものにします。明らかなウソは学びになりません。
- 1店につき、正しいセリフを3問以上、間違ったセリフを7問以上用意します（1プレイで3問と7問を出すため）。

## 4. 選択肢（choices）

- 4つ。そのうち1つは必ず「正しい」という文字列です。
- セリフが間違っている問題では、「どこが違うか」を正しく言い当てた選択肢を正解にします。
- ほかの2つの選択肢は、はっきり誤りと分かるものにします（正解が2つあるように読めないこと）。

## 5. 解説（explain）

- 2〜4文。何が正しいかを、出典に書かれている範囲で説明します。
- 出典に無いことを推測で足しません。

## 6. 書き方

```js
{
  id: "wsl-021",           // 店舗の接頭辞 + 通し番号。既存の id は変えない
  topic: "ファイルの置き場所",
  difficulty: "normal",     // easy / normal / hard
  line: "ゴウのセリフ",
  choices: ["正しい", "正しい指摘", "誤り", "誤り"],
  answer: 1,                // 正解の位置（0から数える）
  explain: "解説",
  source: "公式ページの名前 https://...",
}
```

問題はファイルの末尾に足します。出題の記録は `id` で保存されるので、既存の `id` を変えたり消したりしないでください。

追加したら `npm test` を実行します。
